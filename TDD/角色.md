# [TDD] 游戏属性与 Character 系统技术设计文档

## 系统概述与设计目标

- 目标：建立基于 UE GAS 的低耦合、易扩展的 Character 系统，涵盖玩家角色与 AI 敌人。
- 核心哲学：Character 仅负责视觉表现（Mesh、动画、胶囊体）与组件生命周期；属性计算完全由 GAS（ASC + AttributeSet + GE）驱动；输入、UI、背包、装备各自独立为组件或子系统，通过 Delegate 和 Interface 解耦通信。
- 参考产品：逃离鸭科夫的搜打撤单机体验——探索、战斗、搜刮、撤离。
- 角色不是孤立存在的，TDD 中定义好他与外界环境的接口。

## 类继承

### 角色类

- `ACharacter`（UE 引擎基类）：提供胶囊体、CharacterMovement、骨骼网格体。
- `ADNCharacter`（通用角色基类）：ASC 初始化、AttributeSet 挂载、部位碰撞管理、装备槽位管理、交互接口实现、死亡流程入口。
- `ADNPlayerCharacter`（玩家角色）：相机、输入绑定、背包组件、UI 数据桥接组件。
- `ADNAICharacter`（AI 敌人角色）：AI 感知组件、行为树引用、阵营标记、所给经验值。

### 控制器类

- `ADNPlayerController`：UI 打开/关闭、本地输入接收与路由、相机震动（Camera Shake）。
- `ADNAIController`：AI 感知配置、行为树/状态树运行、自动战斗指令执行。

### AttributeSet 类

- `UDNBaseAttributeSet`：基础属性集（生命/体力/饱腹/水分/速度/视野/声音）。
- `UDNCombatAttributeSet` : `UDNBaseAttributeSet`：战斗属性集（护甲/伤害系数/承伤倍率/枪械控制）。
- `UDNAIAttributeSet` : `UDNCombatAttributeSet`：AI 专用属性集（所给经验值）。

## 组件挂载

### ADNCharacter（基类）组件

- `UCapsuleComponent`：根碰撞胶囊体（引擎）。
- `USkeletalMeshComponent`：主骨骼网格体，挂载 `UDNCharacterAnimInstance`（引擎）。
- `UCharacterMovementComponent`：移动组件，控制行走/奔跑/静步瞄准（引擎）。
- `UAbilitySystemComponent`：GAS 核心，管理 AttributeSet、GE 应用、GA 激活。
- `UDNBaseAttributeSet`：基础属性集实例，注册到 ASC。
- `UDNCombatAttributeSet`：战斗属性集实例，注册到 ASC。
- `UDNBodyPartCollisionComponent`：部位碰撞盒管理（头部 + 身体）。
- `UDNEquipmentComponent`：装备 Spawn 与 Socket 挂载，管理 10 个装备槽位。
- `UDNInteractionComponent`：视线检测 + 交互目标切换 + Server RPC 转发。
- `UDNOutlineEffectComponent`：可交互目标的高亮/描边后处理。

### ADNPlayerCharacter 额外组件

- `UCameraComponent`：相机。
- `USpringArmComponent`：弹簧臂。
- `UDNInventoryComponent`：背包网格逻辑、负重计算、物品存取。
- `UDNPlayerInputComponent`：输入缓冲、长按/连击判定、指令路由。
- `UDNPlayerUIDataBridgeComponent`：ASC Delegate → UI 事件桥接。

### ADNAICharacter 额外组件

- `UAIPerceptionComponent`：AI 感知（视觉/听觉），用于目标发现与索敌。
- `UDNAIAttributeSet`：AI 专用属性集实例。
- `UBehaviorTree`：行为树资产引用，由 ADNAIController 驱动。

## 部位碰撞与受击判定

### 部位定义

角色部位简化为两个碰撞盒：

- 头部（Head）：头部护甲参与减伤，爆头判定。
- 身体（Body）：躯干 + 四肢共用一个碰撞盒，身体护甲参与减伤。

### 部位碰撞盒

- 在角色蓝图上直接放置两个伤害判定盒子`UCapsuleComponent`（头部 + 身体），由 `UDNBodyPartCollisionComponent` 统一管理。
- 碰撞通道：自定义 `ECC_BodyPart`，仅与武器射线/投射物的碰撞通道响应。
- 每个部位碰撞体携带对应的 GameplayTag：`BodyPart.Head`、`BodyPart.Body`。

### 开枪逻辑

- 角色手里有枪且枪里有子弹时，才可触发开枪。
- 玩家：按下开火键触发。
- AI 敌人：视野范围内发现玩家后，通过行为树相关逻辑自动触发。
- 子弹从枪口 Socket 射出，命中后走伤害管线。

### 伤害管线

- 射线/投射物命中碰撞体 -> 获取该碰撞体的 BodyPart Tag -> 查询对应部位的护甲值 -> 计算最终伤害 -> 通过 GE 扣减 Health -> 广播 OnDamageTaken Delegate。
- 伤害 GE 的 SetByCaller 中传入部位 Tag，由 MMC 动态计算护甲减伤与倍率。
- 部位伤害倍率：头部按爆头倍率计算，身体按标准倍率（1.0）。

### 伤害计算公式（来自战斗系统）

- 不暴击伤害 = 武器伤害 × 护甲减免 × (1 + 各元素伤害倍率之和) × 游戏难度伤害倍率
- 暴击伤害 = 武器伤害 × 暴击倍率 × 护甲减免 × (1 + 各元素伤害倍率之和) × 游戏难度伤害倍率
- 武器伤害 = 武器面板伤害 × 子弹伤害系数 × 角色成长伤害倍率 / 单次射击子弹数
- 护甲减免 = 2 / (护甲 - 护甲穿透 + 2)，结果限制在 0~999
- 暴击倍率 = (武器暴击倍率 + 子弹暴击倍率) × (1 + 角色成长暴击倍率)
- 枪械无泛暴击率，玩家准星命中敌人头部即判定为爆头（暴击）。暴击时护甲取头部护甲，未暴击时取身体护甲。
- 枪械具有距离衰减，超距衰减系数为 0.5。
- 近战暴击率 = 近战武器自身暴击率 × (1 + 角色近战暴击率加成)
- 爆炸投掷物不区分阵营，范围内所有单位均受伤害判定（唯一无视阵营保护的攻击方式）。

### 死亡机制

- PC 死亡：上一次死亡生成的遗物消失 -> 本次死亡地点生成遗物 -> PC 在基地重生。
- NPC 死亡：在死亡地点生成遗物。
- 遗物是存放角色死亡时拥有的道具栏、装备栏、背包中物品的容器。
- PC 死亡掉落：枪械1、枪械2、头部装备、眼部装备、胸部装备、耳部装备、背部装备。
- PC 死亡不掉落：手部装备（近战武器）、图腾×2

## 动画与视觉表现

### 动画蓝图（UDNCharacterAnimInstance）

- 状态机层：
  - 基础移动：Idle / Walk / Run / Silent step and aim
  - 死亡：Death （播放特效，删除角色模型，原地生成盒子容器）
- 叠加层（Layered Blend Per Bone，上半身混合）：
  - 切换物品和装备 Montage 
  - 持枪姿势（手枪/冲锋枪/霰弹枪/狙击枪/步枪/近战）（腰射/瞄准），根据 WeaponType Tag 和 是否静步瞄准 切换
  - 换弹 Montage （鸭科夫：不做动画，只是屏幕出现换弹所需时间读条hud和播放音效）
  - 使用物品 Montage（吃食物/喝水/打药）（鸭科夫：不做动画，表现形式为手持物品并且屏幕出现物品使用所需时间读条hud同时播放音效）
  - 受击 Montage（播放特效）
  - 翻滚躲避 Montage（短暂无敌 + 位移）
- IK 层：
  - 脚部 IK（贴地）
  - 手部 IK（握持）

### 动画数据来源

- 移动速度/方向：从 `UCharacterMovementComponent::Velocity` 提取。
- 静步瞄准状态：从 `UCharacterMovementComponent::MovementMode` 提取。
- 持枪类型：从 `UDNEquipmentComponent` 的当前装备 WeaponType Tag 查询。
- 换弹中：从 ASC 当前激活的 GA Tag 查询。
- 受击信息：从 `UDNBodyPartCollisionComponent` 的最后一次受击记录获取。
- 死亡状态：从 ASC 的 `Character.State.Dead` Tag 查询。

### 战斗信息反馈

战斗信息反馈分为五类，均由对应子系统触发，角色只负责表现层的动画与特效响应：

- 音效：武器音效、伤害音效（暴击/普通）、道具使用音效、行为音效（换弹/翻滚）、状态音效（受击/死亡）。
- 飘字：伤害值飘字（暴击标识符 + 数值）、属性伤害飘字（物理白/毒绿/电蓝/火红/空间紫）、行为飘字（AI 换弹时头顶"换弹！"）。
- 动画：行为动画（由 GA 触发 Montage）。
- 特效：状态特效（受击/死亡）、Buff 特效（持续性 Buff/Debuff 的特效）、攻击特效（不同属性攻击的命中特效）。
- 准星样式：爆头/普通命中时的准星变化、换弹/使用道具时的蓝色倒计时圆环。

### 高亮/描边

- 由 `UDNOutlineEffectComponent` 管理。
- 当 `UDNInteractionComponent` 检测到可交互物时，调用目标的 SetHighlight(true/false)。
- 使用 Custom Depth + Post Process 实现。

## 移动与控制

### 移动模式

- 行走：默认移动方式，不消耗体力，传播 `SoundDistance_Walk` 的声音距离。
- 奔跑：按住 Shift，按 `StaminaDrainRate` 消耗体力，传播 `SoundDistance_Run` 的声音距离。
- 静步瞄准：减速移动 + 进入瞄准状态，不消耗体力，声音距离为 `SoundDistance_Walk × 0.5`，改变角色面朝向与子弹散布区域。
- 角色在战斗中可以选择任意方向以行走/跑步/静步瞄准/翻滚方式进行移动。战斗持续期间，战斗空间随交战单位位置变化而移动。

### 玩家输入处理

- 玩家输入经 `UDNPlayerInputComponent` 做输入缓冲与长按/连击判定后分发：
  - 移动输入 -> `UCharacterMovementComponent`
  - 交互输入 -> `UDNInteractionComponent::Server_Interact()`
  - 战斗输入（攻击/静步瞄准/换弹/切换武器/翻滚/使用道具）-> `ASC::TryActivateAbilitiesByTag()`
  - UI 输入 -> `ADNPlayerController`（背包/地图/撤离界面）

### 玩家战斗指令（来自战斗系统）

#### 基础指令

- 攻击：近战与远程投射武器统一通过攻击键触发，通过 GA 执行。
- 移动：四个方向键，根据移动速度和移动时间计算位移。
- 静步瞄准：静步瞄准键触发，减速移动的同时进入瞄准状态，改变角色面朝向与子弹散布区域，降低声音距离。

#### 战术指令

- 使用道具：快捷栏键位触发，通过 GA 播放使用动画并应用物品 GE。
- 翻滚躲避：翻滚键触发，短时间内无敌 + 位移，有 CD，不可连续翻滚。可主动打断换弹、使用道具等战术指令。
- 换弹：换弹键主动触发，或子弹归零时系统强制触发。换弹后扣减背包对应口径备弹。
- 切换武器：切换键触发，在枪械1/枪械2/近战武器间切换。
- 互动：互动键触发，与可交互物（门、容器、撤离点）互动。

#### 动作打断与融合

- 翻滚可强制切断换弹、使用道具等战术指令（主动打断）。游戏无被动打断。
- 所有动作只有前摇 + 生效点，无后摇（收招），因此不需要预输入/指令队列。
- 移动和静步瞄准可以与除翻滚外的所有指令融合执行。

### AI 敌人战斗指令

- 一切战斗指令通过 `ADNAIController` + `UBehaviorTree` 自动执行。
- 基础指令：根据武器对视野内非己方阵营角色执行近战或远程攻击；根据与目标距离、掩体环境、敌我数量自动移动；视野内有敌对目标时自动瞄准。
- 战术指令：根据自身属性与背包物品使用药品恢复血量；部分 Boss 具有翻滚能力；子弹归零自动换弹（无备弹消耗，直接补满）；可开门等环境互动。

### 体力管理

- 奔跑时由 Infinite Duration GE 持续消耗 Stamina。
- 体力 <= 0 强制退出奔跑，直到恢复到阈值（如 20%）才能再次奔跑。
- 非奔跑状态按 `StaminaRegenRate` 恢复。饱腹/口渴 Debuff 降低恢复速度。
- 超重状态（背包负重超过阈值）：额外扣减饱腹值与体力恢复速度。

## 装备槽位（来自物品系统）

角色共有 10 个装备槽位，由 `UDNEquipmentComponent` 管理：

- 死亡掉落：枪械1、枪械2、头部（头盔）、眼部（护目镜）、胸部（防弹衣）、耳部（耳机）、背部（背包）。
- 死亡不掉落：手部（近战武器）、图腾1、图腾2。

每个槽位通过指定的 Socket Tag 将装备挂载到骨骼网格体上。装备的 ItemAttribute（护甲值、伤害倍率等）通过 GE 叠加到角色的 AttributeSet。

## 交互与状态接口

### BPI_Interactable（交互接口）

所有可被角色交互的外部 Actor（地面枪械、战利品箱、撤离点、门、开关、遗物容器）必须实现此接口。定义在共享模块中，Character 与外部 Actor 均可引用。

```cpp
class IDNInteractableInterface
{
    GENERATED_BODY()

public:
    // 交互主逻辑（由 Server RPC 调用）
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "DN|Interaction")
    void Interact(ADNCharacter* Interactor);

    // 是否可以交互（视线检查通过后的二次校验）
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "DN|Interaction")
    bool CanInteract(ADNCharacter* Interactor) const;

    // 高亮开关（由 InteractionComponent 调用）
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "DN|Interaction")
    void SetHighlight(bool bEnabled);

    // 交互提示文本（如"按F拾取 AK-74"）
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "DN|Interaction")
    FText GetInteractPromptText() const;

    // 交互类型（拾取/打开/撤离），决定 UI 图标
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable, Category = "DN|Interaction")
    EInteractType GetInteractType() const;
};
```

### UDNInteractionComponent（交互组件）

- 职责：视线检测 + 交互目标管理 + Server RPC 转发。
- 挂载：`ADNPlayerCharacter`（仅玩家）。
- 工作流程：
  1. C++ Timer（0.15s 间隔，非每帧）执行视线射线检测。
  2. 检测到目标后检查是否实现 BPI_Interactable 且 CanInteract() 返回 true。
  3. 若目标变化：旧目标 SetHighlight(false) + 清理 UI 提示；新目标 SetHighlight(true) + 广播 OnInteractTargetChanged Delegate。
  4. 玩家按下交互键：调用 Server_Interact()（Server RPC）-> 服务器端验证距离与视线 -> 调用目标 Interact(this)。

### 角色对外接口

ADNCharacter 对外暴露以下接口供外部系统调用：

- 供 EquipmentComponent 调用：`GetEquipmentSocketTransform(FGameplayTag SocketTag)` 获取指定 Socket 的 Transform。
- 供 InventoryComponent 调用：`OnInventoryWeightChanged(CurrentWeight, MaxWeight)` 通知负重变化，触发超重检查。
- 供伤害系统调用：`Server_ApplyDamage(DamageCauser, BaseDamage, HitPart, DamageType)` 受击入口，由投射物/近战碰撞触发。
- 供交互系统调用：`Server_PickupItem(APickupBase* Item)` 角色拾取物品入口。

## UI 绑定策略

### 核心原则

- 绝不能让 UI 每帧 Tick 获取角色属性。

### 具体设计

- UI 控件（UDNPlayerHUD、UDNHealthBarWidget 等）在初始化时，通过 `UDNPlayerUIDataBridgeComponent` 向 ASC 的属性变动委托注册回调。
- `UDNPlayerUIDataBridgeComponent::BeginPlay()` 中获取 ASC，对 Health、Stamina、Hunger、Thirst 等关键属性调用 `GetGameplayAttributeValueChangeDelegate().AddUObject()` 绑定回调。
- 回调中通过自定义 Delegate 广播到 UI 子系统，UI Widget 在收到回调后直接 SetPercent/SetText，不做任何缓存。

### 桥接原则

- 单向数据流：Attribute -> ASC Delegate -> UIDataBridge -> UI Widget。
- 零 Tick：UI 只在属性变化时收到回调，不做 GetAttribute() 轮询。
- 屏幕外裁剪：若 Widget 不可见（如 NPC 血条在屏幕外），Widget 注销委托。

### 常态 HUD 显示

- 生命值：HUD 血条，绑定 ASC Health Delegate。
- 体力值：HUD 体力条，绑定 ASC Stamina Delegate。
- 饱腹值：图标 + 百分比，绑定 ASC Hunger Delegate。
- 水分值：图标 + 百分比，绑定 ASC Thirst Delegate。
- 负重/背包格：快捷栏 + 背包面板，绑定 InventoryComponent Delegate。
- 声音感知：方向指示器，事件驱动（附近敌人脚步/枪声触发）。
- 视野：由相机直接控制，无需 UI。

### 敌人 HUD

- AI 敌人血条仅在玩家准星指向敌人或敌人受到伤害时显示。
- 使用 WidgetComponent 挂载到敌人头顶，仅在 WasRecentlyRendered 且距离 < ViewDistance 时可见。
- 敌人护甲、伤害等属性对玩家不可见，制造信息差以增加博弈深度。

## 模块解耦规范

### 职责边界

`ADNCharacter.cpp` 严格控制在 300 行以内，只负责：

- 视觉 Mesh、动画蓝图、胶囊体的创建与生命周期。
- 各组件的 CreateDefaultSubobject 与初始化顺序。

以下职责绝不放 Character 中，必须由各自模块负责：

- 部位碰撞体创建/销毁 -> `UDNBodyPartCollisionComponent`
- UI 打开/关闭、输入路由 -> `ADNPlayerController`
- 相机震动 -> `ADNPlayerController`
- 背包网格逻辑、负重计算 -> `UDNInventoryComponent`
- 装备 Spawn 与 Socket 挂载 -> `UDNEquipmentComponent`
- 属性计算与 GE 应用 -> ASC + AttributeSet（GAS 管线）
- 交互检测与目标切换 -> `UDNInteractionComponent`
- 高亮/描边 -> `UDNOutlineEffectComponent`
- UI 数据桥接 -> `UDNPlayerUIDataBridgeComponent`
- 输入缓冲/连击判定 -> `UDNPlayerInputComponent`
- AI 感知/行为树 -> `ADNAIController`
- 死亡流程/状态机 -> ASC 的 GA_Death + Tag 驱动

### 组件间通信

- Component -> Component：通过 Character 中转，使用 Delegate 或 GAS Tag 状态查询，禁止直接持有其他组件的裸指针。
- Component -> UI：通过 UDNPlayerUIDataBridgeComponent 的 Delegate 桥接。
- Character -> 外部 Actor：通过 BPI_Interactable 接口调用，不直接依赖具体类。
- 外部 Actor -> Character：通过 ASC Delegate 或 GAS Tag 查询，不直接读取 Character 内部状态。
- 所有涉及状态变更（拾取、装备、伤害）的交互必须走 Server RPC，客户端仅做预测显示。

## 边缘情况与异常处理

- 角色死亡：GA_Death 激活 -> 清理所有 Active GE -> 禁用碰撞与输入 -> 播放死亡动画 -> 可选切 Ragdoll。PC 死亡生成遗物后在基地重生；NPC 死亡在死亡地点生成遗物。
- 属性边界保护：AttributeSet 中 PreAttributeChange / PostGameplayEffectExecute 做 Clamp，确保 Health 在 [0, MaxHealth]、Stamina 在 [0, MaxStamina] 范围内。
- 负重超限：InventoryComponent 广播超重事件 -> Character 获得 State.Overweight Tag -> GE 增加饱腹消耗 + 降低移速。
- 饱腹/水分归零：ASC 激活 GA_HungerZero / GA_ThirstZero -> 挂载持续性 Debuff GE。饥饿 Debuff：持续扣血 + 体力恢复减慢。口渴 Debuff：降低移速 + 体力恢复减慢。
- 时间系统联动：饱腹值与水分值随时间流逝持续扣减（HungerDrainRate / ThirstDrainRate）。游戏 24 小时制，1 分钟 = 现实 1 秒，白天 06-18 / 黄昏 18-22 / 黑夜 22-06。黑夜与雨天角色视野变差，特殊敌人刷新。
- 天气系统联动：雨天火属性伤害 -15%，电属性伤害 +20%，通过 MMC 动态计算。
